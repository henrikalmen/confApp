- **G30 closed – the last `code-defect` in the feature, and the fix was a test rather than a behaviour change** (2026-09-02): the nginx `error_log … crit;` directive had **shipped working but unasserted**, so deleting the line left the whole suite green; nothing about the served image changed, a test was added to hold it. `web/test/display-build.test.ts` now asserts three things: that an explicit `error_log` directive exists at all; that its level is one of `crit`, `alert` or `emerg`; and that it sits **inside the server block**, so a location added later cannot inherit a noisier default by omission. The level is asserted as a **set rather than the literal `crit`**, deliberately – a considered move to `alert` should not be a false failure, but `error` and below are refused, because nginx logs the named level *and above* and `[error]` is exactly where the request line carrying the Display Link token is written. That is the case worth guarding: someone lowering the level to "see the errors again" reintroduces the credential leak, and this is what stops them. Both falsifications were run – deleting the line fails with `an explicit error_log directive should be declared: expected null not to be null`, lowering it to `error` fails with `expected [ 'crit', 'alert', 'emerg' ] to include 'error'` – and it was re-confirmed in a real `nginx:alpine` against a refusing upstream: config valid, **zero** raw tokens in any container log, and the 502 still visible as `"GET /api/display/<token> HTTP/1.1" 502`. Verified independently: **92 files / 1555 tests**, typecheck/lint/prettier clean. **All three `code-defect` findings from the gap re-review – G03, G30, G31 – are now closed, each with its falsification actually run, so the verdict's dimensions have nothing outstanding against them.** Six OPEN ledger entries remain and every one is reconciliation-class (`spec-stale` / `design-changed` / `ambiguous-intent`), which routes to Note rather than to the verdict.
- **G03 and G31 closed – the accessibility regression and the SQL guard, both fixed with the falsification run rather than described** (2026-09-02): **G03** was a regression the previous remediation introduced – an `aria-label` on the four Category controls *overrides* their visible text, so a screen reader stopped hearing the destination position the wireframe decision requires. The fix makes the accessible name **contain** the visible string rather than replace it, and derives both from one hoisted value (`upText` / `downText`) so they stay in step through the busy and first/last states where the visible words change; a hand-written label would silently stop matching there. A screen reader now hears `Move down – to position 2 – Tooling` – the destination, plus the Category that was missing. Proved red before green: restoring the overriding label fails with `expected 'Move the category "Tooling" down' to contain 'Move down – to position 2'`, and the test asserts the position text explicitly so it cannot pass on a button that renders no position at all. **G31** had two halves. The *blindness*: the verb-leading filter is replaced by "does this string reference a table", `/\b(from|join|into|update)\s+[a-z_][a-z0-9_]*\b/`, matched **case-sensitively** – which is what separates `from post_it_discard` from `errors.ts`'s "did not come from Google.", since SQL identifiers here are lower snake_case while prose capitalises its nouns, so the false positive that forced the original narrowing is excluded **without an exception list**. The *vacuous self-test*: its first rewrite still passed a complete revert, and the reason is the one worth carrying – asserting against `quotedSql` proves the extractor **works** but not that it is **wired in**, because the function still exists when nothing calls it. The assertion now goes through the combined `statementsIn` against a string occurring exactly once in the codebase. Both falsifications were run: deleting `...quotedSql(source)` from `statementsIn` fails with "the quoted extractor must be wired in", and a single-quoted `and exists (select 1 from ballot …)` added to a module on the display route's closure fails the allow-list naming `ballot`. Verified independently: **92 files / 1554 tests**, typecheck/lint/prettier clean, `visual/session-activities.spec.ts` 18 passed, across three changed files. **Status returns to On Track**; G30 is the single remaining `code-defect` and seven OPEN ledger entries still gate the completion-presentation.
